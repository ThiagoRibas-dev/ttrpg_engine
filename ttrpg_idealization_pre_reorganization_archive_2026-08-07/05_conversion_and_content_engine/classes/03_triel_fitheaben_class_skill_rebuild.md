# Triel Fitheaben — Class Skills and Magic Mastery Rebuild

**Status:** Non-canonical conversion / class-modeling exercise.  
**Relationship:** This is Revision 2 of `02_triel_fitheaben_level_20_provisional_conversion.md`. It supersedes that file’s illustrative Class Skills and magical-access assumptions; its Attribute, resource, equipment, and broad feature-conversion work remains useful unless replaced here.

## 1. Purpose and New Inputs

This revision applies the following accepted framework decisions to Triel’s actual source progression:

```text
Cleric base Magic Mastery Class Skills:
  Divine, Spirit, Life, Death, [own alignment].

Triel’s own alignment:
  Good.

Divine Domains:
  Each grants its mapped additional Tradition access and its own
  non-magical Feature package.

Spellcasting Class / Prestige Class extra Investments:
  Each Class table decides.
  For this exercise, every source level that grants a Spell Slot
  Advancement also grants one Magic Mastery-only Investment.
```

The last line is a test assumption, not a new universal rule. It is the ordinary DEC-097 benchmark applied consistently to this conversion.

### 2.2 Proposed inherited-divine-casting convention

To make current-Class Skill access work for spellcasting Prestige Classes, this exercise uses the following **provisional convention**:

```text
A Prestige Class that advances an existing divine spellcasting class:
  lists the Tradition Skills supplied by that advanced casting package
  as eligible Magic Mastery Class Skills.

A new Domain granted by the Prestige Class:
  adds its mapped Tradition to that eligible set at the level gained.
```

Thus, Ordained Champion, Knight of the Raven, and Righteous Cohort do not own an entirely new spell list. They advance Triel’s existing Divine access package, while their own Domain / Feature grants can expand it. This is a conversion hypothesis that needs a later general multiclass presentation rule.

| Rank | Traditions | Reading |

## 6. What This Exercise Teaches

1. **The Cleric’s fixed base package is useful.** Divine, Spirit, Life, Death, and own alignment create an immediately recognizable religious caster before Domains enter play.
2. **Domains add identity without becoming duplicate spell lists.** War, Law, and Sun provide three distinct secondary Traditions; Healing overlaps Life but still has a meaningful Domain Feature.
3. **One Magic-only Investment plus Domain Tradition Grants prevents early overflow.** The character retains all 25 baseline Investments for martial, knowledge, social, and Craft competence while developing five Master and three Veteran Traditions.
4. **Spellcasting Prestige Classes need inherited-access wording.** Without it, current-Class Skill access makes a divine casting PrC unable to improve the actual Traditions it advances. The proposed inherited-divine-casting convention is therefore a key future Class-table presentation question.
5. **There is no generic protected-primary-Tradition entitlement.** Any protected Tradition progression must be an explicit Class-table grant.
6. **Source-class skills convert cleanly into the current taxonomy.** Legacy Concentration becomes a spellcasting procedure rather than a Skill; generic Craft becomes a selected Craft specialty; legacy Knowledge (history) and (the planes) become focused Lores until broader Knowledge content is added.

## 7. Open Conversion Assumptions

- The exact Class tables, any explicit protected-Tradition grants, inherited-casting multiclass procedure, and per-Class Magic Investment grants remain future Class content.
- The conversion treats the source’s generic `Craft` class skill as access to a selected Craft specialty, not every Craft specialty. The present `Craft — Alchemy` selection is unsupported by the recorded source ranks and awaits replacement or explicit user confirmation.
- `Lore — History` and `Lore — Planes` are provisional focused specialties because the current Knowledge list has no broad History or Planes Skills.
- The exact Class Skills for the non-SRD Prestige Classes are thematic conversions built from their source lists, requirements, Domains, and features. They are not final class content.
- Exact spell acquisition, preparation, Spell Slot table, companion rules, and individual Feature procedures remain open.
