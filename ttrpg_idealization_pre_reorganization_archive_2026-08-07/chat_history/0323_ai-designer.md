# Turn 323 — AI-Designer

Yes. A fixed die-size pool is a very common RPG architecture. In those systems, progression comes almost entirely from:

More dice.
More successes per roll.
Automatic successes.
Better reroll/push mechanics.
More specialized permissions.
More favorable consequences.

The die size itself does not advance.

1. Shadowrun — d6 Dice Pools

Shadowrun is one of the clearest examples.

A character builds a pool from:

text
Attribute + Skill + Equipment + Circumstances

Then rolls d6s and counts hits, usually based on a fixed success face threshold.

Progression comes from:

Higher Attributes.
Higher Skills.
Specializations.
Gear.
Cyberware.
Magic.
Temporary modifiers.
Edge or reroll effects.
More dice in the pool.

Difficulty is usually represented by:

Number of hits required.
Opposed rolls.
Thresholds for extended tests.
Limits on how many hits can count in some editions.

The system does not need d8, d10, or d12 for ordinary advancement because a character can progress from:

text
3d6 → 6d6 → 10d6 → 15d6

The main problem is pool-size inflation and rolling fatigue at high levels.

2. Year Zero Engine — d6 Dice Pools

Games such as Mutant: Year Zero and Forbidden Lands use pools of d6s generated from:

text
Attribute + Skill + Gear

A six usually produces a success.

Progression comes from:

More Skill dice.
Better Attributes.
Better gear.
Talents.
Extra successes.
Pushing rolls.
Resource expenditure.
Special abilities.

Difficulty is usually represented by:

The number of successes required.
The number of successes generated by the environment or opposition.
Opposed rolls.
Consequences rather than increasingly high target numbers.

The fixed d6 makes the system easy to teach. The pool size and number of required successes provide most of the difficulty curve.

3. World of Darkness — d10 Dice Pools

World of Darkness generally uses pools of d10s.

A character’s pool comes from:

text
Attribute + Skill + equipment or circumstance modifiers

A fixed range of faces counts as successes.

Progression comes from:

Higher Attributes.
Higher Skills.
Specialties.
Equipment.
Merits.
Rerolls.
Exceptional success thresholds.
Extra successes.

Difficulty is usually controlled by:

Target success number.
Number of successes needed.
Opposed pools.
Extended tests.
Exceptional-success rules.

Again, the die size stays fixed. The character improves by generating more chances and more successes.

4. Blades in the Dark — d6 Pools

Blades uses a smaller d6 pool based on Action rating.

The result is based primarily on the highest die:

text
1–3: Bad outcome
4–5: Partial outcome
6: Full success
Two or more 6s: Critical

Progression comes from:

Increasing Action ratings.
Special abilities.
Effect level.
Position.
Devil’s bargains.
Pushes.
Assistance.
Extra dice.

Difficulty is not primarily represented by a higher target number. Instead, it is represented by:

Position: how dangerous failure is.
Effect: how much the action accomplishes.
Consequences.
Clocks.
Resistance costs.

This is a very useful example of fixed dice with multiple axes of outcome rather than a large DC ladder.

5. Fate and Cortex-Style Systems

These are not always strictly d6 pool systems, but they demonstrate another fixed-die philosophy.

Progression comes through:

Skill ratings.
Assets.
Distinctions.
Stress.
Complications.
Extra effect.
Narrative or tactical permissions.

Difficulty is often expressed by:

Opposed totals.
Fixed target values.
Effect thresholds.
Consequence severity.

The important lesson is that fixed dice can support substantial character differentiation if the game has multiple progression vectors besides die size.

6. What Fixed d6 Pools Do Mathematically

Suppose a d6 produces a success on 5 or 6.

Then each die has:

text
P(success) = 2/6 = 33.33%

For a pool of N dice:

text
Expected successes = N × 33.33%

The probability of at least one success is:

text
P(at least 1) = 1 − (2/3)^N

Examples:

Pool	Chance of at least one success
1d6	33.33%
2d6	55.56%
3d6	70.37%
4d6	80.25%
5d6	86.83%
6d6	91.22%
8d6	96.10%
10d6	98.27%

This produces a smooth reliability curve through pool size alone.

If success requires a 6 instead:

text
P(success) = 1/6 = 16.67%

then:

Pool	Chance of at least one 6
1d6	16.67%
2d6	30.56%
3d6	42.13%
4d6	51.77%
5d6	59.81%
6d6	66.51%
8d6	76.72%
10d6	83.84%

The target face or Required Success count provides the difficulty axis.

7. How a Fixed d6 Game Handles Progression

A fixed-die system typically uses one or more of these methods.

More dice
text
2d6 → 4d6 → 6d6 → 8d6

This increases reliability.

More required successes
text
DC 5 (1)
DC 5 (2)
DC 5 (3)

This increases task complexity without changing the die.

Different success thresholds
text
Success on 4+
Success on 5+
Success on 6

This changes how difficult each die is, but can create another target-number axis.

Automatic successes
text
5d6 +1 automatic success

This represents high-tier mastery or powerful equipment without needing larger dice.

Extra-success effects

The number of successes can determine:

Degree of effect.
Damage.
Critical results.
Progress.
Additional targets.
Reduced consequences.
Special permissions

High-tier characters can do things ordinary characters cannot:

Act at extreme range.
Ignore certain conditions.
Affect larger areas.
Use equipment in extraordinary ways.
Bypass immunities.
Convert failures into partial outcomes.
8. Fixed d6 Versus Our Current Model

Our current model has two major advancement vectors:

text
Die Size
Pool Size

A fixed d6 model would reduce that to:

text
Pool Size

with additional vectors such as:

text
Required Successes
Automatic Successes
Traits
Permissions
Equipment
Conditions
Benefits of fixed d6
Much simpler probability model.
No d4/d6/d8/d10/d12 ceiling interaction.
No need to ask how Floors interact with die size.
Equipment and Competency both add dice cleanly.
Easier conversion to Shadowrun or Year Zero-style systems.
More predictable pool mathematics.
Fewer discontinuities when Attributes improve.
Costs of fixed d6
Attribute identity becomes less important unless Attributes affect pool size in a strong way.
A STR d6 and STR d12 no longer have different numerical ceilings.
High DCs must be represented by:
More Required Successes.
Higher success thresholds.
Automatic constraints.
Permissions.
Large pools can become physically cumbersome.
Pool-size inflation may replace modifier inflation.
The distinction between raw capability and reliability becomes less direct.
9. Important Floor Problem

Our new pool-derived Floor model fits fixed dice very naturally:

text
1d6 → Floor 1
2d6 → Floor 2
3d6 → Floor 3
4d6 → Floor 4
5d6 → Floor 5

But once pools go above five dice:

text
8d6 → Floor 5
10d6 → Floor 5

because of the current final-die-size cap:

text
Floor ≤ die size − 1

This means a fixed d6 system would naturally make Floors saturate at 5.

That is not necessarily bad. It would mean:

Pool size continues improving success probability.
Floor reliability caps at 5.
Automatic Successes or Required Successes handle higher-tier certainty.

This is actually a clean bounded model.

Using the tier-aligned Competency model:

Master	4d6	4

Equipment could then add dice:

text
Veteran character:

  5d6 final
  Floor 5

A Legend character might use:

text
6d6 baseline
+3 equipment dice

The character’s improvement beyond Hero would primarily come from:

More dice.
More automatic successes.
More Required Success capacity.
More permissions.
Stronger equipment traits.
Mythic effects.
11. Why Our Current d4–d12 Model May Still Be Valuable

The variable-die model gives us a very intuitive distinction:

text
Die Size:
  What magnitude can I reach?

Pool Size:
  How reliable am I?

Floor:
  How bad can my result be?

That is excellent for simulationist design.

A fixed d6 model simplifies the probability but loses the direct expression of physical scale:

text
A giant and a halfling both roll d6s.

They can still be differentiated through pool volume, but the giant’s peak strength is no longer represented by a larger die.

Recommendation

I would not immediately switch to fixed d6.

Instead, use the fixed-die games as a comparison model for our current calibration:

Compare our d8, d10, and d12 curves against equivalent fixed-d6 pools.
Measure how much of our complexity comes specifically from Die Size.
Determine whether Die Size produces meaningful fictional differences that Pool Size alone cannot represent.
Test fixed d6 as a possible alternate resolution model.
Continue with the current model unless fixed d6 clearly improves simplicity without losing important simulationist distinctions.

The most useful lesson from these games is not necessarily “use d6.” It is:

A stable probability curve can be built from fixed dice if pool volume, Required Successes, Automatic Successes, and Permissions are doing enough of the progression work.

That gives us a useful benchmark for deciding whether our second Die Size axis is worth the additional complexity.
