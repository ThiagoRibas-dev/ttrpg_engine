# Turn 17 — User

Another knob we have is the hybrid dice system, so when you are, say, doing an opposing roll of attack vs defense, a character that's proficient in attacking could have a set floor based on his class or something like that, same thin for the defender. Kind of like having one die that's always fixed at a certain number.

Let's math this out using a python script to calculate the odds of 5 levels of competency, untrained, trained, expert, master, and legendary, over the 20 levels.

The idea is not for these to be abstracted proficiency "ticks" like in PF2e, but something that the underlying math of the system will account for, essentially creating hard caps by engineering the possible permutations, and a player has granular control over during character creation and advancement. We as designers will have these hard caps in mind even if they aren't explicit to the players.
